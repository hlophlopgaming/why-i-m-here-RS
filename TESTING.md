# Проверки

## Автоматические

```bash
cargo fmt --all --check
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
git diff --check
```

Тесты не открывают окон и не завершают пользовательские процессы. Они проверяют
общую сессию для окон одной программы, независимость таймеров, отсутствие
таймера до ответа, фиксацию режима, отмену без завершения, однократное истечение,
валидацию длительности/цели, историю, совместимость настроек, IPC и аргументы CLI.
Скачивание зависимостей и сборка FLTK требуют сети и C++ toolchain.

Кросс-проверка Windows без сборки FLTK:

```bash
rustup target add x86_64-pc-windows-msvc
cargo check -p core -p platform -p daemon --target x86_64-pc-windows-msvc
```

Сборка UI в Linux отклоняет отсутствие `wayland-client`, `wayland-cursor`,
`wayland-protocols`, `xkbcommon` или `pkg-config`. После установки зависимостей
нужно выполнить `cargo clean -p fltk-sys`: наличие пакетов само по себе
не пересобирает ранее закешированный FLTK. CI дополнительно проверяет
`#define FLTK_USE_WAYLAND 1` в фактически сгенерированном заголовке FLTK.

## Ручная проверка деморежима

Проверить отдельно в Plasma 6 Wayland и Windows 10/11, на русском и английском.

1. `cargo run -p app -- --demo`: открывается форма цели отдельным процессом
   `why-here ui goal`, а родительский процесс своих окон не создаёт.
2. Не отвечать на форму несколько секунд: отсчёт не начинается. Попробовать
   закрыть форму: она остаётся открытой и объясняет, что нужна цель.
3. Пустая цель отключает «Начать». Проверить ограничение времени от 1 до
   1440 целых минут: недопустимое значение не должно запускать таймер.
4. Ввести цель с кириллицей и длительность 1 минуту. После «Начать» форма
   закрывается, отдельный UI показывает цель и убывающий таймер, затем результат
   имитации закрытия окон. Открытые программы продолжают работать.
5. «Ещё раз» открывает форму с предыдущей целью. Escape на панели сессии
   выходит без экрана имитации завершения.
   Кнопка «Закончить сессию» сразу показывает имитацию выбранного действия.
6. `cargo run -p app -- --demo --show`: выбрать завершение процессов,
   открыть форму цели,
   закрыть форму цели. Появляется результат имитации завершения процессов;
   ни одна другая программа не завершается.
7. Закрыть настройки: деморежим выходит. Повторно запустить: длительность 15 минут,
   режим закрытия окон, пустая цель. Настройки предыдущего запуска не сохранены.
8. Повторить с `--language en`: все подписи и ошибки формы на английском.
9. Проверить каждый экран: `cargo run -p app -- ui <экран> --demo`, где экран —
   `goal`, `timer`, `reminder`, `settings`. Ответ закрывает отдельный просмотр;
   таймер заканчивается автоматически, остальные экраны дальше не открываются.
10. Во время таймера усыпить компьютер дольше оставшегося времени. После
    пробуждения появляется результат, а отсчёт не продолжается с прежнего места.
11. После обычного закрытия проверить отсутствие дочерних UI-процессов.
    Аварийно завершить только демонстрационный родительский процесс: UI должен
    закрыться при EOF на stdin. Не завершать чужие процессы для проверки.

В Linux окно должно иметь app_id `org.local.WhyHere`. В Plasma проверить это
через инструменты KWin или запустить отдельный экран с
`FLTK_BACKEND=wayland WAYLAND_DEBUG=client`: в stderr должна присутствовать
отправка `set_app_id("org.local.WhyHere")`. Проверить читаемость при масштабах
100% и 200%, навигацию Tab/Shift+Tab и отправку цели Enter.

## Память и отсутствие фоновой нагрузки

Использовать `cargo build --release -p app`, а не отладочную сборку или Cargo.
Пока открыта форма, отдельно измерить RSS родительского и UI-процесса
(`/proc/<pid>/status` в Linux, инструменты измерения рабочего набора в Windows).
Родительский процесс не должен периодически просыпаться без активного таймера.
Фиксированных лимитов RSS нет; сравнивать с замерами в `BENCHMARKS.md`.
Процент CPU и память нельзя
выводить из успешного прохождения unit-тестов.

Первичный замер 2026-10-15, Linux x86_64, релизная сборка, открыта форма цели:
около 8,5 МиБ RSS у родителя и 25 МиБ у UI. Бюджет превышен. В окружении
не установлен `wayland-protocols`, поэтому FLTK автоматически отключил
Wayland-бэкенд и использовал X11. Эти результаты не подтверждают работу
нативного Wayland; для неё нужны установленный пакет протоколов и новая сборка.

Повторный замер 2026-10-15 после сборки с протоколами Wayland 1.49 во временном
каталоге: родитель — 9096 КиБ RSS (8,9 МиБ), форма цели — 27132 КиБ (26,5 МиБ).
Бюджет по-прежнему превышен. Сборка содержит `FLTK_USE_WAYLAND 1`; все четыре
экрана проверены с `FLTK_BACKEND=wayland`, а трассировка протокола подтвердила
`set_app_id("org.local.WhyHere")`. Каждый UI завершился при EOF от родителя.
За секунду ожидания формы у родителя не изменились счётчики CPU utime/stime.
Кросс-проверка `core`, `platform`, `daemon` для Windows прошла, но запуск
Windows-приложения не проверен. Проверка виджетов мышью/клавиатурой, сна и
масштабирования ещё не выполнена. Само переключение с X11 на Wayland
не устранило превышение RSS; уменьшение потребления памяти остаётся отдельной
нерешённой задачей.

## Платформенные проверки

Бэкенды KWin/Win32 реализованы. Нативные тесты ниже используют только собственный
тестовый процесс. Принудительное уничтожение процессов не реализовано; не
проверять закрытие на пользовательских программах или документах.

## Новая компоновка и элементы управления

- Проверить тёмные настройки при минимальном размере 760×740 и растянутом окне:
  списки растут, подписи и кнопки остаются видимыми.
- Удалить все демопрограммы: открытие формы недоступно. Добавить демопрограмму:
  она выделяется и форма запускается для неё. Повторное добавление не создаёт
  дубликатов; имена отображаются как текст, без форматирующих команд браузера.
- Выключить отслеживание: открытие формы недоступно; включить — снова доступно.
- В форме «Начать» недоступна для пустой цели и доступна после ввода текста.
  Выбрать 5/15/30 минут и проверить начальный отсчёт.
- Для сессии 1 минута выбрать предупреждение за 1 минуту: панель сразу показывает
  янтарное время и предупреждение. При интервале 0 предварительного сигнала нет.
- Перетащить компактную панель за текст. «Закончить сессию» показывает
  результат, а Escape отменяет сессию без имитации завершения.
- Выбрать английский язык на панели настроек: следующая форма на английском.
- Недоступные элементы прозрачности и отдельной кнопки переподключения KWin/Win32
  объясняют ограничение во всплывающей подсказке.

IPC имеет версию 6: инициализация содержит приложение и полные настройки,
обновление таймера — флаг визуального предупреждения, каталог программ
передаётся порциями. Старые сообщения версий 1–5 отклоняются; демон и UI должны запускаться из одного исполняемого файла.

Проверки после смены компоновки: 16 unit-тестов, Clippy, форматирование,
релизная сборка и кросс-проверка Windows-кода прошли. В собственных X11-окнах
прямыми адресными событиями проверены ввод цели, включение «Начать», пресет
5 минут (300 секунд), удаление и добавление демопрограмм, передача выбранной
программы. В Wayland сняты реальные окна настроек, формы и панели; сквозной IPC
проверен для выбора программы и досрочного завершения в обоих режимах.
Замеры RSS выше относятся к прежней компоновке; после изменения размеров окон
память повторно не измерялась. Бюджет пока не считается выполненным.

## Установленные программы и звук

1. В настройках открыть «Из установленных программ…»: каталог загружается без
   зависания основного окна. Поиск работает по имени и ID без учёта регистра.
2. Добавить выбранную программу или дважды щёлкнуть строку: она выделена
   в основном списке. Повторное добавление не создаёт дубликата. Приложение
   не должно запускаться или завершаться; сессия остаётся демонстрационной.
3. Закрытие окна выбора закрывает только его. Повторное открытие использует
   уже загруженный каталог; закрытие настроек завершает все собственные UI.
4. По умолчанию звук выключен. Включить его и запустить сессию 1 минута
   с предупреждением за 1 минуту: должен прозвучать ровно один сигнал, а не
   сигнал каждую секунду и ещё один при истечении. При интервале 0 он звучит
   только по окончании. При досрочном завершении до предупреждения звука нет.
5. Linux: при отсутствии pw-play или недоступном PipeWire ошибка попадает
   в stderr, а таймер и результат продолжают работать. Windows: проверить
   реальное воспроизведение через PlaySoundW. Глобальную громкость не менять.

Каталог Linux проверен на временных XDG_DATA_HOME/XDG_DATA_DIRS, включая
приоритет пользовательских файлов, Hidden/NoDisplay, локализованные имена
и ID с несколькими `.desktop`. Сквозная проверка UI использует каталог из 601
временной записи: общий размер превышает 64 КиБ, но отдельные IPC-сообщения
в лимите. Проверены поиск, выбор и сохранение полного ID. Заглушка pw-play
получила ровно один корректный WAV за предупреждение и истечение сессии.
Настоящий PipeWire дополнительно проверяется потоком с `--volume=0`; это
не подтверждает слышимость на конкретных колонках или наушниках.

GUI-проверка окна выбора, требующая запущенной графической сессии:

```bash
FLTK_BACKEND=wayland cargo test -p ui native_picker_updates_and_filters_while_open -- --ignored
```

Этот тест прошёл в настоящем Wayland; протокол подтвердил app_id
`org.local.WhyHere`. Он также выявил и помог исправить панику отладочной сборки:
`set_format_char('\0')` запрещён обёрткой fltk-rs. Теперь оба списка используют
ненулевой служебный маркер; имена с управляющими символами отклоняются,
обычные имена с `@` отображаются буквально.

Итог проверок этого этапа: 21 тест без GUI прошёл, отдельный GUI-тест
прошёл вручную в нативном Wayland, Clippy и кросс-проверка Windows-кода
прошли. Воспроизведение WAV через настоящий pw-play с громкостью потока 0
завершилось успешно. Слышимость на аппаратуре и запуск в Windows не проверены.

## Постоянные настройки

`cargo run -p app -- --show` открывает постоянные настройки без запуска сессий.
Для ручных проверок задайте временный `XDG_CONFIG_HOME` (Linux) или `APPDATA`
(Windows), чтобы не менять личный файл.

1. На чистом профиле список пуст, длительность 15 минут. Сохранение доступно
   без выбранных программ и при выключенном отслеживании.
2. Добавить программу из каталога, изменить параметры и язык, нажать
   «Сохранить и закрыть». Повторный запуск `--show` восстанавливает значения.
3. Изменить параметры и закрыть окно или нажать «Закрыть настройки»: файл не меняется, демон остаётся в трее.
4. В `settings.json` добавить неизвестное поле: следующее сохранение сохраняет его.
   Старый JSON только с `duration_secs` получает значения по умолчанию остальных полей.
5. Повредить JSON: запуск выдаёт ошибку, исходный файл остаётся прежним.
   При ошибке записи открытой панели появляется сообщение; после устранения
   причины можно повторить сохранение без повторного ввода.
6. `--demo --show` использует временные настройки, не читает и не меняет файл.
7. Проверить Windows отдельно: первое создание файла и замену уже существующего.

Тесты хранилища работают во временных каталогах: создание, повторная запись,
кириллица, история и точный ID, неизвестные поля, повреждение, недопустимые
значения, лимит 1 МиБ и отказ замены. На Linux проверяются права файла 0600.
IPC v4 добавил режим панели и подтверждение сохранения.

```bash
FLTK_BACKEND=wayland cargo test -p ui native_settings_save_without_apps_or_tracking_and_allow_retry -- --ignored
```

Проверка этапа сохранения: 25 headless-тестов, Clippy и кросс-проверка
`core`/`platform`/`daemon` для Windows прошли. Новый GUI-тест прошёл в Wayland.
На временном XDG-профиле сквозной сценарий настоящих процессов демона и UI
(через адресные X11-события только собственному дочернему окну) подтвердил
сохранение, повторную загрузку, сохранение неизвестного поля, отказ перезаписи
повреждённого файла и успешную повторную попытку без закрытия панели.
Системные CMake 4.4.3 и wayland-protocols 1.49 позволяют обычную релизную сборку
без временных PATH/PKG_CONFIG_PATH. Личные настройки не менялись.
Замена файла на настоящей Windows и новый RSS не проверены.

## Трей и единственный экземпляр

Обычный запуск и `--show` открывают настройки, `--background` не создаёт окон.
Повторный запуск передаёт запрос единственному экземпляру. Закрытие окна
или «Сохранить и закрыть» завершают только UI. Выход — пункт «Выйти из приложения»
в меню трея; при выходе завершаются только собственные дочерние UI.

```bash
dbus-run-session -- cargo test -p platform ownership_forwarding_and_release_use_one_owner -- --ignored
FLTK_BACKEND=wayland dbus-run-session -- cargo test -p app --test background -- --ignored
```

Первый тест проверяет владение D-Bus-именем без очереди, передачу запроса и
повторное получение имени после выхода. Второй запускает собственного
StatusNotifierWatcher на отдельной шине, проверяет регистрацию и RGBA/ARGB-иконку,
отсутствие UI в фоне, повторный `--background`, отказ неизвестной версии протокола,
открытие через трей, единственное окно после `--show` и выход через меню трея.
Настройки временные; существующие приложения пользователя не затрагиваются.
IPC UI v5 добавляет команду показа уже открытого окна. Протокол управления
экземпляром v1 отдельно проверяет версию, команду и язык.

На настоящих Plasma и Windows вручную проверить видимость иконки, оба пункта
меню, повторное открытие после закрытия настроек и фокус окна (композитор может
ограничить активацию). Изменение языка применяется к следующему UI, язык трея —
после перезапуска демона. Убийство/ошибка собственного UI не завершает демон.
Windows требует отдельной проверки Explorer, mutex/pipe, быстрой серии повторных
запусков и завершения при ожидающем соединении pipe; кросс-компиляция не заменяет
запуск на Windows.

## Каталог Windows без PowerShell

Автоматический тест `apps_folder_catalog_on_worker_thread` перечисляет AppsFolder
в отдельном потоке, проверяет непустой результат и валидность ID. В Windows 10/11
открыть выбор программы, сравнить названия и ID классических и Store-приложений
с `Get-StartApps`; повторить с кириллическими названиями. При открытии каталога
дочерний PowerShell появляться не должен. Скорость и пик памяти измерять отдельно:
сценарий `background.rs` каталог не открывает.

Для изменений каталога/IPC/иконки прошли 31 локальный headless-тест, clippy Linux
и Windows, проверка D-Bus-владения на отдельной шине и шесть последовательных
проходов релизного сценария памяти. GitHub Actions для `1586c18` прошли на Ubuntu
и Windows; нативный тест AppsFolder в Windows тоже прошёл. Проверки CI не
подтверждают работу GUI и производительность каталога на пользовательском Windows.

## Реальные сессии и автозапуск (IPC v6)

Выпуск v0.2.0 содержит новые возможности; архивы v0.1.0 содержат предыдущую
реализацию. Обычные сессии всегда используют запрос закрытия
окон, а режим kill остаётся имитацией деморежима.

```bash
node kwin/bridge.test.js
FLTK_BACKEND=wayland dbus-run-session -- cargo test -p app --test real_sessions -- --ignored --nocapture --test-threads=1
cargo build -p ui --example window_fixture
WHY_HERE_WINDOW_FIXTURE="$PWD/target/debug/examples/window_fixture" FLTK_BACKEND=wayland \
  cargo test -p platform native_kwin_observes -- --ignored --nocapture --test-threads=1
```

Первый тест проверяет JS-блокировку и watchdog на макете. Второй запускает настоящий
демон и UI на отдельной D-Bus-шине с макетом KWin: отмена вопроса, истечение таймера
и EndNow закрывают оба окна одной программы; другие программы не затрагиваются.
Для имитации ответа тест пишет только в stdout-pipe собственного дочернего UI.
Третий использует настоящий KWin и уникальное имя сервиса: два окна отдельного
FLTK-примера сворачиваются, восстанавливаются после ответа/выхода бэкенда и
закрываются. Состояние minimized проверяется через KWin getWindowInfo. Личные
настройки не меняются; скрипт теста хранится во временном каталоге.

Windows, только в интерактивной сессии и без другого экземпляра WhyHere:

```powershell
cargo build -p ui --example window_fixture
$env:WHY_HERE_WINDOW_FIXTURE = "$PWD\target\debug\examples\window_fixture.exe"
cargo test -p platform native_win32_blocks -- --ignored --nocapture --test-threads=1
```

Тест копирует пример в уникальный временный путь, контролирует и закрывает только
его окна. Этот тест не подтверждён запуском на Linux; кросс-компиляция не заменяет
Windows GUI. Отдельно проверить UWP (CoreWindow под ApplicationFrameHost),
повышенные права (не блокировать; показать ограничение), повторное открытие,
несколько независимых программ и сон дольше оставшегося времени.

Ручной сценарий на отдельной тестовой программе:

1. В обычных настройках выбрать тестовую программу, сохранить, запустить её.
   Окно свёрнуто до ответа. Два окна одной программы дают один вопрос.
2. Ввести цель и время: окна восстанавливаются, появляется таймер. Проверить
   «Закончить сессию» и отдельно истечение времени: программа получает обычное
   закрытие. Тестовый документ с изменениями может запросить сохранение.
3. Закрыть вопрос без ответа: тот же запрос закрытия, без принудительного kill.
4. Удалить программу из отслеживания, отключить отслеживание или выйти из трея:
   отменить сессию и восстановить окна без закрытия программы.
5. Включить «Запускать при входе в систему», сохранить: проверить Exec/Run с
   абсолютным путём в кавычках и `--background`. Войти в ОС заново: только трей,
   без окна настроек (Windows — релизная GUI-сборка). Отключить и сохранить:
   запись удалена. Простое закрытие настроек отменяет изменение флажка.
6. В деморежиме автозапуск недоступен. Тесты записи используют временный
   XDG_CONFIG_HOME или отдельный HKCU\Software\WhyHereTests, не реальный Run.
7. Перенести бинарник и повторно сохранить включённый автозапуск. Проверить путь
   с пробелами и кириллицей. При отказе записи автозапуска прежние настройки
   восстанавливаются; неизвестные поля settings.json сохраняются.
